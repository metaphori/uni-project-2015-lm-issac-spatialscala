 \begin{abstract}
 \footnotesize
 
 The Scala programming language and ecosystem provide developers with powerful tools for tackling complexity in software development,
   especially with regards to concurrency and distribution.
   
 This project approaches the development of an 
  aggregate programming framework with Scala and (possibly) the Akka actor framework.
 
 The goal is to investigate whether these tools are adequate for such an effort 
  and what key issues and challenges need to be tackled. 
  
\end{abstract}

\subsection{Design choices}

\begin{itemize}
 \item Eventual consistency
    \begin{itemize}
    \item A device does not wait to collect the updated states of all its neighbors 
      before calculating the next state; it will use its best current knowledge
    \item Processing and sensing are intertwined
    \end{itemize}
 % Eventual consistency is a consistency model used in distributed computing to achieve high availability 
 %that informally guarantees that, if no new updates are made to a given data item, eventually all accesses 
 %to that item will return the last updated value
\end{itemize}


\subsection{Description}

Basic concepts

\begin{itemize}
 \item A device \hlb{Dev[S,I]} has a name, a state, and a behavior
 
 \item The behavior of a device can be seen as a function of its state \ttb{S => S} (\hlb{DevMooreBehavior})
 or a function of its state and inputs 
 \ttb{(S,I) => S} (\hlb{DevMealyBehavior}), producing the next device's state
 
 \item A \hlb{Space[E,P]} is an abstraction for a spatial container of elements: 
   elements can added to a certain location, elements can be retrieved, and the space can be queried for the location of an element
 \begin{itemize}
    \item A \hlb{MutableSpace[E,P]} allows for the move and removal of elements
    \item A \ttb{Basic3DSpace[E]} is a mutable space of elements of type E which are located by means of 3D points (x,y,z)
 \end{itemize}
 
 \item A \hlb{DistanceStrategy[E,P,D]} defines how distances and locality (neighborhoods) 
   are calculated for a given \texttt{Space[E,P]}
 \begin{itemize}
    \item \ttb{EuclideanStrategy[E]} defines the euclidean distance (Double) on a 3D space
 \end{itemize}
 
\end{itemize}

Actor system structure

\begin{itemize}
 \item \hlb{DevActor[S,I]} is an actor that wraps a \ttb{Dev[S,I]}
 \item \hlb{SpaceManagerActor} is an abstract actor that represents a spatial container for actors.
 \ttb{SimpleSpaceManagerActor} is a 3D space manager actor with an euclidean distance strategy
 \item \ttb{SamplerActor} and \ttb{GUIActor} sample the states of the device actors to provide a 
   representation of the evolution of the system along time
\end{itemize}

Actor system dynamics

\begin{itemize}
 \item A device actor
    \begin{itemize}
    \item When started, registers itself to the space manager
    \item Then, it periodically schedules the next state transition
    \item When it is not processing anything, it can respond to the other actors requesting its current state
    \end{itemize}
\end{itemize}


\subsection{Issues}

Issues and challenges

\begin{itemize}
\item Conceptual integrity and (functional) separation of concerns
\item Simulation of locality
    \begin{itemize}
    \item In the real world, locality is enforced by physical laws
    \end{itemize}
\item Who are responsible for keeping track of device positions?
    \begin{itemize}
    \item The space manager only?
    \end{itemize}
\item Multiple consistency requirements and synchronization patterns between devices
\end{itemize}
